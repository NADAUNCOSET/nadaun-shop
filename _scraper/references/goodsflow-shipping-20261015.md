# 굿스플로 송장 연동 — 2026-10-15

대표 요청: 주문관리에서 선택 주문을 접수하고 송장을 편하게 인쇄하며 번호와 배송 상태를 자동 반영한다. 기존 아임웹 배송 설정에서 CJ대한통운/로젠 승인완료, 기본 배송 로젠을 확인했다. 이는 아임웹 계약이며 우리몰 API 연결 완료를 뜻하지 않는다.

## 구현과 실행 조건

- 관리자 로그인·동일 출처 검증 후, 실결제 확인된 구매 배송 대기 주문만 1~25건 미리보기/접수한다. 부분 출고·렌탈·반품 송장 자동 접수는 이번 범위 밖이며 기존 개별 처리 기능을 유지한다.
- 공식 Sellers Open API `https://api.goodsflow.io/` Swagger 계약으로 구현. 전용 우리몰 API 키와 승인된 출고지/택배 계약이 필요하다. `SHOP_GOODSFLOW_API_KEY`, `SHOP_GOODSFLOW_MODE=live`, `SHOP_GOODSFLOW_ENABLED=true`가 모두 갖춰지기 전에는 비활성 상태다. 키는 Git/문서/로그에 저장하지 않고 비공개 운영 환경변수로만 연결한다.
- 실제 PG 재조회 → DB 예약/조회 큐를 같은 트랜잭션으로 저장 → 접수 POST 1회. 응답 유실은 고정 uniqueId 조회로 복구하고 재접수하지 않는다. 조회 결과가 불명확하면 확인 대상으로 남긴다.
- 인쇄 URI는 동일 계약의 선택 주문만 서버에서 발급하고 공식 굿스플로 호스트로 연다. URI는 1분·1회용이며 저장/로그/미리 열기를 하지 않는다. 재인쇄는 별도 체크가 필요하다.
- PRINTED/TRANSFERRED에서는 송장번호만 반영한다. PICKUP/IN_TRANSIT/DLV_START에서 출고 수량과 배송 중을 반영하고 COMPLETED에서 택배사 배송 완료로 표시한다. 과거 단계가 뒤늦게 와도 배송 완료를 되돌리지 않는다.
- 암호화된 주문 고객 데이터 안에 송장 작업 상태를 보관한다. 자동 출고 건은 수동 송장 등록/수정과 충돌하지 않도록 막았다. 자동 배송 완료 이벤트를 탭 집계와 엑셀의 배송 확인 출처에도 반영한다.
- `shop_shipping_sync` 추가 테이블을 적용했고 운영 주문0건/큐0건을 재확인했다. 기존60초 Mac 작업 스케줄 loaded 확인. 켜진 서비스는 작업당 최대2건/건당5분 간격으로 조회하며 관리자 화면에서도30초마다 최대2건을 조회한다. 현재 고객 주문과 굿스플로는 모두 OFF다.

## 검증과 남은 연결

실제 서비스·메모리SQLite·외부통신 차단 fixture로 가상 구매2건을 접수했다. 미리보기2/접수 POST2/인쇄 URI2, PRINTED 배송대기2 → PICKUP 배송중2 → COMPLETED 배송완료2 전이를 확인했다. 기존 수동배송완료1건과 합쳐 상단 완료3건 집계도 확인했다. 중복/동시 접수, 응답 유실, 버전충돌, 주소오류, 결제취소, 계약만료, 위험 출력URL, 로그인 차단 테스트를 포함한다.

실제 굿스플로 계정/API 키는 미확보다. 대표에게 기존 발급 여부/저장 위치를 문의했으며 응답 대기. 기존 아임웹 인증 토큰을 추출하거나 재사용하지 않았다. 실제 고객 접수0건, 실제 택배 발급/프린터 출력/Windows 실기기 검수는 미완료다. 운영 연결 전 테스트 환경의 승인 계약/번호 발급/라벨 스캔과 실제 PC 출력 검증이 필요하다. 현재 구현은 자체 어댑터와 테스트 근거이며 실제 외부 서비스 성공을 보장한 완료 상태가 아니다.
